model-effort-router

Pick the right Claude model and effort for every task and subagent, automatically, and check the rules on real tasks.

GitHub repositoryBenchmark report

A Claude Code plugin. Before a subagent or worker starts, it reads the task (a story, a GitHub issue or a plain prompt), the labels people put on it and the repository it touches, and chooses Sonnet or Opus and an effort level. Every choice comes with its reasons. Guessed risk never raises the bill; only explicit lines, labels and configured paths do. A stronger model is tried only when the worker itself failed. Standard-library Python 3.9+, MIT, no dependencies.

Install

/plugin marketplace add islamkmansoori/model-effort-router
/plugin install model-effort-router@model-effort-router

Subagents are then routed automatically by a hook. To route a task by hand: /route-task <file | owner/repo#123 | "prompt">.

How it decides

What the task saysModel and effort
**Critical:** yes, a critical label, or a configured critical pathopus, xhigh
**Risk:** money, security or data, a mapped label, or a configured risk pathat least opus, high
9 points or moreopus, high
6 to 8 pointssonnet, high
5 points or lesssonnet, medium

Points come from size, acceptance criteria, dependencies, signals in the text (schema, permissions, UI, open questions, shared files, concurrency), and the repository (touched files, untested code, often-changed files). An optional assessor (one Haiku call, under a cent) estimates the size of vague tasks.

Questions

Which Claude model should a Claude Code subagent use?

It depends on the task. The benchmark shows the cheaper model solves easy tasks for a fraction of the cost while harder ones need Opus; the router chooses per task.

How do I set the model and effort of a subagent?

Per call with the Agent tool's model and effort, per subagent with model: and effort: in its frontmatter, or per session with claude --model opus --effort high. This plugin's hook fills the Agent tool's parameters for you.

Why does my subagent ignore the effort I set?

CLAUDE_CODE_EFFORT_LEVEL overrides every other effort setting. CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 makes subagents ignore the model they are given. router.py check-env names both.

Is climbing from the cheapest model up the cheapest strategy?

Not always: failed attempts are paid for too. The benchmark compares the options, including the cheapest rung that would have worked in hindsight.
